# BOSS 直聘聊天记录获取研究

## Chrome 扩展

已在项目根目录的 `extension/` 制作本地 Chrome 扩展原型，并安装到 ego「爬虫」及“您的 ego”两个空间。浮窗支持修改职位状态、编辑公司和 JD 备注及删除职位；采集页面负责账号、同步和导出。两个空间是不同的 BOSS 账号，已分别验证 5 个会话、16 条消息，以及 38 个会话、207 条消息的本地入库和数据隔离。真实多页历史、实际发消息和发简历后的识别尚未验证。使用方法、数据范围和限制见 [扩展说明](../../extension/README.md)。

## 结论

已在 ego 的「爬虫」空间恢复登录，并验证一个**有限的只读导出原型**。它只导出列表中第一个已读会话的第一页历史，并不能导出全部聊天记录。首次运行时要保持该空间打开并登录 BOSS 直聘。没有发送消息或修改资料；为避免改变未读状态，研究没有打开带未读标记的会话。

此次页面显示 5 个会话及“没有更多了”，其中 4 个带未读标记。搜索框写着“搜索30天内的联系人”；这并不能证明会话列表或历史消息只保留 30 天，也不能证明 5 个就是账号的全部会话。原有聊天标签曾无响应，研究使用同一爬虫空间中的另一个标签。

## 运行样本原型

依赖：已安装并运行 ego-browser，存在名称为「爬虫」的空间，空间中打开已登录的 `https://www.zhipin.com/web/geek/chat`；终端中可以调用 `ego-browser`。需要 Node.js 20 或更新版本；脚本通过本机 Node.js 启动 ego 的浏览器脚本环境，不需额外安装 npm 包。

在项目根目录运行（会访问真实账号，仅在需要研究样本时手动执行）：

```bash
npm run research:export
```

脚本刷新聊天页，检查列表首个会话没有未读标记后打开它，捕获网页正常发出的第一页历史请求，并把返回的消息保存在项目根目录的 `private-exports/` 下带时间戳的 JSON 文件中。若首个会话未读、页面未登录、无法捕获请求或接口返回异常，脚本会停止；它不会自动尝试其他会话。成功后保留聊天页并交还空间。捕获的消息字段可能包含姓名、聊天内容、联系方式、附件地址等隐私，请只在本地使用。脚本不保存请求 URL、cookie、token 或 `securityId` 字段；导出目录已加入 `.gitignore`，文件权限设为 `600`、新建目录权限设为 `700`。忽略规则不能替代对文件的访问控制。

启动脚本根据自身位置解析项目根目录的 `private-exports/`，再把绝对路径传给 ego；移动项目无需修改脚本，不依赖 ego 的工作目录或环境变量。运行时应确认爬虫空间只有一个可用聊天页：若有多个，脚本选择活动聊天页，否则选择列表中的最后一个，不能保证总能避开无响应的旧标签。登录失效、验证码、页面结构变化或浏览器空间被占用时，先在同一空间恢复后重试。失败时不保证已保存文件；重试会生成新文件，需自行检查并去除重复文件，脚本没有断点续传或自动去重。

## 实测与范围

- 会话列表：当前页面呈现 5 个会话并显示列表结束；未验证超过一页时的加载行为、其他筛选条件、已删除会话或账号全量覆盖。
- 历史记录：首个已读会话触发 `GET /wapi/zpchat/geek/historyMsg`，首次请求的 `page=1`、`c=20`、`maxMsgId=0`；响应包含 `hasMore`、`messages`、`minMsgId`。本样本返回 3 条，`hasMore=false`；网页呈现 2 条消息项，包含普通文本和卡片。响应中 3 条记录的 ID 各不相同，两次样本获取的 ID 一致。未检查未呈现记录的语义；接口报告结束不等于证明账号历史完整。
- 性能：两次样本从点击到获取响应分别约 105、109 毫秒；这个数字不含打开浏览器、刷新页面、登录或写文件，样本太小，不能推算批量导出速度。
- 消息类型：在这一个会话观察到文本和卡片，响应记录含 `type` 3 和 4。图片、文件、语音、撤回消息及其他类型未验证；附件是否可下载、链接是否过期也未验证。原型只保存返回的消息结构，不下载附件。
- 翻页与恢复：尚未观察到 `hasMore=true` 的历史，因此 `minMsgId` 与后续请求的对应关系、顺序、重复边界和限流均未验证。原型只保存第一页，并将服务器返回的 `hasMore` 和 `serverReportsEnd` 写入文件；即使为 `false` 也不能据此保证历史完整。

## 后续研究

需要在不改变未读状态的前提下找到可安全测试的多页历史及会话列表，验证游标、时间跨度、重复消息和恢复策略；另需识别所有消息类型并比较网页与账号实际可见记录，才能评估全量导出的可行性。当前原型不应被视为备份或完整性证明。
