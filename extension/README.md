# BOSS 沟通助手（本地扩展）

这是用于 ego「爬虫」空间的 Chrome Manifest V3 扩展原型。它在浏览器 IndexedDB 中整理 BOSS 网页当前加载的会话、消息、公司和关联职位；不会向其他服务器上传数据，不会自行发送消息、申请或简历。聊天内容、公司、职位和手动状态都留在安装此扩展的浏览器个人资料中。

## 使用

在 Chrome / ego 扩展管理页开启开发者模式，选择“加载已解压的扩展程序”，加载项目根目录下的 `extension/`。加载前先在项目根目录运行 npm ci 和 npm run build，或使用 npm run dev 启动持续构建。源码位于 extension/src/，Vite 将可执行入口生成到 extension/dist/；加载目录仍是 extension/。迁移后重新加载现有扩展并刷新站点即可，数据库名称、版本和账号命名空间不变。

目录迁移后，浏览器保存的旧加载路径不会自动更新。未固定 `key` 的解压扩展换路径可能生成新的扩展 ID，原 IndexedDB 不会自动迁移；原安装应先保留，并在可用的采集页面导出重要数据，再处理加载路径。当前导出仅提供备份，不提供 JSON 导入恢复。不要直接卸载有数据的旧扩展。

1. 在同一个「爬虫」空间登录 BOSS 直聘并打开聊天页。扩展加载后需要刷新已打开的 BOSS 页，页面右下角会出现公司与职位浮窗：首行是公司名称，下面每行展示一个 JD 及状态。同公司 JD 按最早已知对话时间从早到晚排列，当前 JD 只高亮、不置顶。没有可用时间的 JD 放在末尾，时间相同或都缺失时按固定记录 ID 排序。新消息、状态和备注变化不会改变顺序；补充到更早历史时，才可能按新发现的首次时间调整。
2. 点击浮窗的“采集与导出”打开采集页面。点浮窗的“JD 看板”或浏览器扩展按钮可直接进入看板，并在页面顶部切换视图。采集时先在“本地记录”选择账号，再在“采集进度”查看本次已处理的会话和失败数。点“更新采集”按网页当前已加载的会话逐个读取职位详情和历史消息。在“采集请求间隔”可为当前账号保存 1 至 30 秒的最短间隔，默认 3 秒，下一轮采集生效。插件逐个发送主动请求，新打开的页面首次请求前也会等待设定的时长，每发出 20 次再休息 20 秒；会话多时需要较长时间，请保持聊天页打开。可以停止；已保存的记录会保留。出现限流、验证、登录失效、异常响应或网络错误时，插件停止整轮更新，不自动重试；限流或验证异常后同一页面至少等待 5 分钟，并遵守更长的服务器 `Retry-After`，其他请求错误后等待至少 1 分钟；处理问题后可手动再次更新；目前会从列表开头重新读取，已保存的消息按会话和消息 ID 去重，并非从中断位置续传。
3. 所有 JD 使用同一套卡片布局，当前 JD 以浅绿底色标出。窄屏首次打开时浮窗收起，点击方向箭头查看。消息显示不下时，点击消息右侧的方向箭头查看全文。直接点击任一 JD 的状态文字即可在浮层选择新状态，再点击“确认修改”保存。选择“跟随自动判断”并确认，可撤销手动状态。公司与 JD 的备注都显示在各自标题下方，点击标题右侧的备注图标打开编辑浮层。编辑时暂停浮窗自动刷新，保存失败或切换编辑入口时会保留备注草稿。刷新网页会清除未保存的草稿。
4. 公司备注与 JD 备注在浮窗中分别保存，不会因自动采集而覆盖；同一条备注在其他页面改变时，保存会提示冲突并保留草稿。历史待定 JD 合并后出现不同备注时，会在“合并前的备注”中保留原文。每个 JD 只有一个当前状态，人工标记优先；面试阶段统一标记为“面试中”。采集页面可将当前账号的数据（含备注）导出为 JSON，导出文件包含隐私，请妥善保管。
5. 职位列表的右侧详情区和独立职位详情页使用与聊天页相同的浮窗，可修改状态、公司备注和 JD 备注。当前职位用 ID 匹配，已保存的职位保持原排序。能识别公司、标题和 ID 的新职位会显示临时行，保存 JD 备注或状态时才入库。只保存公司备注时仅更新公司记录，浏览和切换职位不会创建对话。浮窗中的 JD 标题可点击，在新标签打开详情页。
6. 打开 BOSS 个人中心的“感兴趣 → 职位收藏”，网页当前加载的收藏岗位会自动保存，包括已下架但仍提供职位 ID 的记录。只读取职位收藏列表，忽略公司收藏和侧栏推荐。同一 JD 与已保存的沟通记录合并，保留人工状态和备注；收藏是独立标识，在浮窗显示“已收藏”，不替代沟通状态。职位页明确显示已收藏时也会保存该 JD。取消收藏后，有对话的职位继续显示沟通状态；没有对话的职位从浮窗隐藏，底层记录和备注保留，重新收藏或产生对话时恢复展示。收藏岗位不会虚构联系人、消息或对话。分页列表仅处理网页已加载部分，不会因某条记录未出现在当前页而取消其标识。
7. 点击浮窗内职位标题右侧的垃圾桶图标，确认后删除对应 JD。删除仅作用于当前网页账号，会清除该 JD 的本地状态、备注和相关状态事件；已有对话、聊天消息、其他职位及 BOSS 网页上的收藏不会被删除。为避免刚删除的记录重新出现，后续聊天同步或收藏观察不会自动重新收录同一 JD。
8. 点击公司名称右侧的垃圾桶图标可删除公司本地记录。确认后会清除该公司的备注，并删除旗下所有 JD 的本地记录和状态事件。已有对话和消息保留，后续聊天同步或收藏观察不会重新收录该公司及其 JD。

## 覆盖与准确性

采集页顶部的「JD 看板」按当前账号的 JD 状态分组，推进较深的阶段在上方。点击组名可独立收起或展开，组内按状态时间从近到远排序。每个 JD 占一行，展示最后一条真人对话及时间、状态时间和备注，薪资、地点、经验、学历合并在最后的「职位条件」列。完整消息尚未采集时，满足归属、发送方向和时间条件的列表消息标为「聊天摘要」。自动状态使用判断当前状态所依据的聊天消息时间，手动状态使用对应的操作记录时间，缺少可靠时间时显示「—」。顶部的「活动时间」滑条可选当天、最近 1–15 天、1–3 个月或不限；「当天」从浏览器本地时间的零点开始，范围内状态或对话任一有更新即可显示。默认不限，滑条和各组展开状态保存在当前浏览器。点击带链接的 JD 标题可打开职位详情，点击备注可展开全文。若刚在浮窗改完状态，可点「刷新记录」更新看板。

浮窗的“面试中”可根据 BOSS 的面试邀约和接受卡片自动判断。“对方拒绝沟通”“面试通过”和“面试失败”由用户手动设置。手动状态优先，选择“跟随自动判断”可恢复最新自动状态。

看板中，公司列和「状态说明与备注」列的备注图标分别编辑公司、JD 备注。「状态时间」下的「修改状态」会先打开状态选项，确认后立即更新分组。

- 限速作用于插件在同一聊天页面中主动发送的采集请求，不控制网页自身的请求。不同账号或不同浏览器空间的页面分别计数；刷新页面会重置本页的间隔和休息计数。因此请避免在多个空间同时启动采集，也不要频繁刷新页面后重复更新。降低频率不能保证不会触发网站限制。
- 更新范围是**网页当前已加载的联系人列表**。本次账号列表显示 5 个并提示“没有更多了”，但这不能证明账号所有历史会话都在列表中；搜索框的“30 天”提示也不足以推断完整范围。网页接口或结构改变、断线、风控、被删除的会话等都可能导致缺失。
- 扩展尝试以 `minMsgId` 翻历史页，检测游标停滞并逐页保存，最多每会话 100 页；目前只验证了 `hasMore=false` 的单页，**多页游标行为尚未经过真实账号验证**。单页的服务器终止标记不等于账号历史完整。
- 在一个未读会话上读取职位详情及第一页历史，刷新稳定后仍有 4 个未读会话，未观察到未读数量变化；这只是小样本，不能证明所有接口、所有账号和所有历史页没有副作用。用户自己打开未读对话时，BOSS 网页可能正常改变其未读状态。
- 职位与公司按网页提供的当前职位 ID 和公司名整理；名称只做精确归一匹配，不能自动识别公司别名。一个联系人换过多个职位时，旧历史往往缺少可验证的职位标识：扩展不把缺少职位标识的历史用于多 JD 会话的职位状态。单 JD 会话则按当前联系人职位关联，仍需人工核对；页面未提供职位 ID 时保留会话，不虚构 JD。
- 自动状态优先识别有效的 BOSS 面试邀约和接受卡片，显示“面试中”。收到明确的取消或拒绝卡片后，重新按简历系统提示、附件简历请求和最近真人发言判断。同一对话涉及多个 JD 时，需要能确认卡片所属的 JD。已有本地聊天记录会按新规则重新判断。遇到多条不同简历提示时间相同或缺失、消息没有发送方向等情况时，可能显示“待确认”。
- 更新只保存网页返回的部分消息字段和卡片标题、说明及无敏感查询参数的 HTTPS 地址；不下载图片、语音、附件，也不保存 cookie、token 或 `securityId`。网页脚本可影响页面观察数据，识别结果不是防篡改证据。账号以用户 ID 的散列隔离；更换账号后在采集页面切换，不会将不同账号合并。
- 公司和 JD 备注每条最多 10,000 字。保存只修改扩展本地数据库，不调用 BOSS 写接口。浮窗嵌入当前网页，网页脚本可能读取已显示的备注内容；本地保存不等于与网页隔离。
- 浏览器清除扩展数据、卸载扩展或个人资料损坏可能导致本地数据库丢失。重要记录请自行导出备份。新版扩展会在构建成功后自动重载，已打开的真实 BOSS 页面在下次导航或刷新时使用新版。

## 开发验证

项目根目录运行 `npm ci` 后执行 `npm test` 和 `npm run check`；仅运行扩展测试使用 `npm run test:extension`。自动化测试使用模拟数据，不连接 BOSS 或发送信息。

## 本地 mock

同一份扩展也匹配 `http://127.0.0.1:4173`，便于在 [`mock/`](../mock/README.md) 中开发、验证和单测。启动 mock 后直接刷新页面即可出现浮窗，不需要另建测试包。

- 插件按页面 origin 判断环境：只有本地 mock 页面跳过采集间隔、周期休息和异常冷却；真实 BOSS 至少等待设置的请求间隔，并继续执行周期休息和异常冷却。
- mock 账号在哈希前加入 `boss:mock:` 命名空间，即使页面用户 ID 与真实账号相同，也会归入不同账号记录；采集页面中切换账号查看，不会混入真实数据。
- mock 覆盖插件当前涉及的状态、排序、备注与失败分支：`normal` 含 16 位联系人（多 JD、同 JD 多人、无消息 JD、多类简历标签、审核中、撤回、纯系统消息、仅 dialog 的请求卡片、长 HTML 文本、缺少 JD、未知未读）；`unknown_direction` 演示列表方向回退与待确认；`ambiguous_resume` 演示同时/无时间冲突；其余场景覆盖分页、空列表、部分加载、游标停滞、429/401/403/500、非 JSON、结构异常、业务码和慢接口。场景切换会在插件中新增一套独立记录，旧场景数据保留。具体操作与覆盖对应见 [mock 说明](../mock/README.md)。
- JD 排序使用已采集到的最早消息时间。首次导入时，尚未采集到消息的 JD 先按记录 ID 排在末尾，随采集完成会落到真实时间位置；完整采集后新消息、状态和备注变化不再改变顺序。
- 模拟环境仅用于开发，姓名、公司、职位和聊天内容均为虚构。

复测时发现旧版会在再次查看历史后覆盖原有的采集范围记录，现已修复：每页等待数据库提交确认，自动采集与被动查看分别记录；修复后在 38 个会话上重新更新，再抽查 5 个会话，被动读取后 38 个连续采集记录仍然保留。同一账号的并发更新互斥、停止会发往启动标签；职位由多个联系人沟通时按联系人保留自动证据，避免一条会话变化抹掉另一条，后者目前通过模拟测试。两次真实账号样本都没有超过一页的会话；多页只通过模拟测试，依然不能保证平台接口的真实多页兼容性。

浮窗 JD 排序在真实账号中验证：同一公司两个职位的首次消息时间相差约 6 天时，按较早到较晚显示；当前打开的较晚职位仅高亮，未置顶。

限速版本在「爬虫」空间仅用一个会话做了少量真实请求验证：详情与历史两次请求的发起时间相隔约 3.9 秒；停止后没有继续采集，已保存数据保留。20 次后的休息、异常响应及限流等待使用模拟测试验证，未主动触发网站风控进行测试。

本次测试中，为避免 BOSS 网页反复弹出访问本机其他应用和服务的权限请求，已在“您的 ego”空间对该请求选择“屏蔽”；如以后需要相关功能，可在该空间的网站权限设置中修改。
